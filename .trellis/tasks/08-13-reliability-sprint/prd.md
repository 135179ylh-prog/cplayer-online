# PRD - CPlayer 可靠性冲刺

## 目标

收尾并验证当前 GitHub Pages 部署，修复移动端页面隐藏/后台播放结束后的自动切歌边界，补齐歌手搜索完整分页与触摸滚动回归，并提供不泄露敏感信息的本机播放故障诊断。

## 范围

- 播放结束后的自动切歌：顺序、单曲循环、列表循环、随机。
- 播放页面隐藏、下一首网络延迟、下一首自动播放被浏览器拒绝。
- 歌手搜索：接口报告总数、多页重复、空分页、失败重试、旧请求污染、触摸 Pointer Events 滚动。
- 桌面 1280×800、手机 390×844 的 Playwright 回归。
- 本机播放故障诊断：只展示脱敏的播放状态/失败分类/重试与页面可见性信息，不自动上传。
- 更新本任务的 PRD、设计、实施计划、研究和验证记录；每个修复独立提交、推送和线上验收。

## 隐私约束

- 不把 API 密钥、API 地址、请求查询字符串或完整媒体 URL 写入诊断记录、导出内容、云同步或网络请求之外的持久化数据。
- 诊断记录不保存歌曲名称、歌手、封面和播放进度；只保留必要的模式、队列索引、错误分类、媒体错误码、网络状态、页面可见性和时间。
- 既有的播放进度恢复记录保持原有本机行为，不纳入诊断报告，也不上传云端。
- 诊断记录有界、仅本机内存可见；清空页面或点击清除后立即丢弃。

## 验收标准

1. 页面隐藏后歌曲自然结束时：顺序模式播放下一首，单曲循环重新播放当前首，列表循环回到首首，随机播放下一个随机顺序项；同一次结束不会重复切歌。
2. 结束切歌遇到下一首接口延迟时，旧媒体的重复 `ended` 事件不能跳过目标歌曲；目标请求完成后只提交一次。
3. 下一首 `audio.play()` 被 `NotAllowedError` 拒绝时，播放器保持暂停并显示可操作提示；用户点击播放或 Media Session 播放后可以恢复，不触发错误跳过。
4. 搜索结果按接口报告的总数加载；重复 ID 不重复显示；空页不会在仍有总数缺口时错误地把结果标记为完成，也不会造成无限请求。
5. 搜索后续页失败保留已有结果并支持重试；旧查询迟到响应不能进入新查询；桌面和手机从结果按钮区域发起触摸 Pointer Events 拖动并滚到底部可以加载下一页。
6. 播放故障诊断在本机可查看，内容脱敏且不包含 API 密钥、API 地址、完整媒体 URL、歌曲文本或播放进度；不产生上传请求。
7. 运行定向桌面/手机测试和完整 `npm run verify`；推送后等待 Pages 工作流成功，并在线验证页面就绪、Service Worker 控制和本轮关键行为。
8. 不覆盖或删除工作区已有未提交改动，不修改或清空用户歌单数据。

## 实施状态（2026-08-04）

- 播放结束切歌和搜索分页已分别独立提交并完成 Pages 工作流与线上验收；本机诊断的实现与桌面/手机定向回归已完成，诊断独立发布仍待完成。
- 诊断记录实际采用当前页面内存中的最近 32 条环形缓冲，并通过设置页查看/清除；未新增 localStorage、IndexedDB、云同步或上报接口。

## 非目标

- 不改变 ChKSz API、排序或每页 30 首的上游契约。
- 不引入服务端代理，不把 API 密钥移到代码或云端。
- 不重做已有歌单、云同步和页面视觉系统。
