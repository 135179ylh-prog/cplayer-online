# PRD - 同步上游 API 响应兼容层

## 背景

原作者的新播放器已继续演进，但当前项目还包含四种播放模式、本地队列、云同步、回收站和故障诊断等本地改造。整站覆盖会破坏这些数据和行为契约。

## 本步目标

- 复用上游公开播放器已验证的 HTTP 状态解码思路。
- 将非 2xx 响应的状态、上游安全错误文案和重试属性统一交给请求层。
- 保持现有歌曲 ID、歌单备份、IndexedDB、播放进度和 API 密钥存储方式不变。
- 诊断和错误对象不得包含密钥、地址、完整音频 URL、歌单内容或播放进度。

## 不在本步范围

- 不整站复制原作者页面。
- 不引入 QQ/酷狗歌曲 ID 前缀或改变既有歌单格式。
- 不上传任何本机播放或账号数据。

## 验收标准

- 2xx JSON 原样返回。
- 4xx/5xx JSON 被转换为带状态和安全 code 的错误；5xx 可按现有策略重试，4xx 不重试。
- 非 JSON 错误响应仍有稳定的用户可分类错误。
- 单元测试覆盖成功、无效 JSON、401、429、503 和重试边界。
- Pages 资源契约、桌面/手机浏览器回归和完整质量门禁通过。
