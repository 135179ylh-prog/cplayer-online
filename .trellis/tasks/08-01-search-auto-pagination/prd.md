# PRD - 搜索结果自动分页

## 目标

修复用户搜索歌手时只看到首屏结果的体验问题。现有 ChKSz 搜索接口已经支持 `limit` 和 `offset`，本任务不改变上游排序或结果范围，只让用户继续滚动时自动请求下一页。

## 范围

- 桌面搜索面板和手机搜索面板共用同一套分页状态与去重规则。
- 搜索结果接近滚动容器底部时自动加载下一页。
- 保留“加载更多”按钮，方便键盘、辅助技术和不使用滚动的用户。
- 自动加载失败时保留已显示歌曲，并提供“重试加载”。
- 新搜索、切换面板或过期请求不能把旧结果追加到当前查询。
- 未登录、离线播放器、API 密钥本机保存和歌单持久化行为不变。

## 不在范围内

- 不新增服务端代理，不把 Linux.do 主题里的 Flask 后端搬到 GitHub Pages。
- 不承诺上游没有收录的歌曲一定能搜索到。
- 不一次性渲染数百首歌曲，不改变 ChKSz 的搜索排序。

## 验收标准

- [x] 首屏仍请求 `limit=30&offset=0`，首次结果显示真实进度。
- [x] 桌面和手机滚动到结果底部附近时自动请求下一页，并追加去重后的歌曲。
- [x] 自动加载过程中不重复发请求，最后一页隐藏按钮并显示完整进度。
- [x] 手动“加载更多”仍可用；后续页失败时结果不清空且可重试。
- [x] 旧查询的迟到响应不会污染新查询，数字歌曲 ID 直达流程不变。
- [x] 桌面 1280×800、手机 390×844 浏览器回归通过，`npm run verify` 通过。
- [ ] 独立提交、推送、Pages 部署成功后完成线上搜索验收。
