# PRD：待同步项目可恢复化

## 目标

让已登录用户看见“待同步”背后的具体歌单和操作，而不是只看到一个数字；在网络恢复后可以单项重试或全部重试，并继续保留本机优先、失败可观察、不会静默覆盖的约束。

## 范围

- 在账号与云同步卡片中列出当前账号的待同步歌单、操作类型、歌曲数量和最近更新时间。
- 提供每一项的“重试”和统一的“全部重试”入口。
- 单项重试只处理选中的歌单；其他待同步项目继续保留。
- 全部重试继续沿用现有同步决策、冲突预览和回收站/历史版本逻辑。
- 离线时保留列表但禁用重试按钮，联网后可直接操作。
- 健康检查和脱敏诊断报告复用同一份最近错误记录，不重新拼接或暴露原始错误对象。
- 桌面 1280×800、手机 390×844 覆盖“断网 → 刷新 → 显示具体待办 → 单项重试 → 全部重试”。

## 非目标

- 不改变云端表结构、RPC 契约或 outbox 的唯一键。
- 不把 API 密钥、地址、会话 token、完整错误对象或歌曲私有字段写入待同步展示或诊断报告。
- 不在未登录时展示其他账号的歌单名称；未登录仅显示需要登录对应账号的提示。

## 验收标准

1. 当前账号有 2 个待同步项目时，设置页显示两行具体歌单和操作，待同步数量与行数一致。
2. 点击其中一行“重试”后，仅该项目从 outbox 消失，另一行仍保留；云端只收到被选中的歌单变更。
3. 点击“全部重试”后，成功项目全部清空；冲突或失败项目仍可见且不会被覆盖。
4. 断网时待办列表仍可见，重试按钮禁用；恢复网络后无需刷新即可重试。
5. 健康检查中的云同步项目和导出的脱敏报告包含与“最近错误”相同的安全提示文本，不包含密钥、地址、token 或原始错误对象。
6. 未登录播放器仍可完整播放和使用本机数据，且不显示其他账号的具体待办内容。
7. 桌面/手机定向回归与完整 `npm run verify` 通过。
