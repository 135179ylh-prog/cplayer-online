# 搜索结果完整分页

## Goal

修复歌手搜索只显示前 30 首的问题，增加桌面与手机共享的分页加载、总数反馈和竞态保护。

## Requirements

- 普通文本搜索首次加载 30 首，随后允许用户继续加载，直至接口报告的结果全部展示。
- 桌面搜索面板和手机搜索面板行为一致，并显示“已显示 N / 共 M 首”的真实进度。
- 加载下一页时保留已显示歌曲；请求失败可重试，不把已有结果替换成空状态。
- 用户发起新搜索后，旧查询和旧分页响应不得追加到新结果中。
- 对跨页重复歌曲按歌曲 ID 去重，防止接口重复页造成重复显示或无限加载。
- 数字歌曲 ID 的直接播放流程、搜索后收藏/加入队列和 API 密钥本机保存合同保持不变。

## Acceptance Criteria

- [x] 首次请求包含 `limit=30` 与 `offset=0`；点击“加载更多”后请求 `offset=30`。
- [x] 两页各 30 首且总数 65 时，界面从 30 首追加到 60 首，并显示还可继续加载。
- [x] 最后一页加载后按钮消失，进度显示实际去重数量与接口总数。
- [x] 下一页失败时首屏歌曲仍可播放、加入队列或收藏，且加载按钮可以重试。
- [x] 快速切换查询时，较慢的旧分页响应不会污染当前结果。
- [x] 桌面 1280×800 与手机 390×844 浏览器用例通过，手机按钮不小于 44px 且页面无横向溢出。
- [x] `npm run verify` 全部通过，并更新 Service Worker 缓存版本和 Trellis 验证记录。

## Notes

- 不改变 ChKSz 的搜索排序，也不承诺上游未收录的歌曲能够被搜到。
- 不一次性渲染几百条结果，避免手机首屏请求和 DOM 压力过大。
