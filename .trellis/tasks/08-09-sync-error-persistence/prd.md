# PRD：同步失败可恢复化——最近错误持久化

## 目标

让已登录用户在同步失败后刷新页面，仍能看到最近一次失败原因和“重试同步”入口；错误记录必须按账号隔离，不能把其他账号的错误显示出来。

## 范围

- 将最近一次云同步错误保存到本机 `localStorage` 的 `cp_cloud_last_error`。
- 记录仅包含账号 ID、时间和已脱敏的用户提示，不保存密钥、地址、token、歌曲或完整错误对象。
- 登录会话恢复时读取当前账号的错误记录；成功同步后清除该账号的错误记录。
- 退出登录、切换账号时只清理内存展示，不把其他账号的错误泄露到当前账号。
- 桌面和手机覆盖“同步失败 → 刷新 → 错误仍可见 → 重试成功”的回归。

## 非目标

- 本次不改变待同步项目的展示结构，不新增单项重试或全量重试以外的同步策略。
- 不改变本地优先、冲突处理、健康检查或云端数据模型。

## 验收标准

1. 已登录账号同步失败后，刷新页面仍显示“同步出错”、最近错误和“重试同步”。
2. 恢复网络并点击重试后，状态变为“已同步”，待同步数量归零，最近错误隐藏，本机待办被清空。
3. 预置其他账号的 `cp_cloud_last_error` 时，当前账号不会显示该错误，也不会把其内容写入当前账号的错误提示。
4. 错误记录不包含 API 密钥、API 地址、token、歌曲内容或完整错误对象。
5. 桌面 1280×800、手机 390×844 定向测试和完整 `npm run verify` 通过。\n
