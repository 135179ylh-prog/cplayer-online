# PRD - 发布可追踪与手机可靠性冲刺

## 目标

在不改变用户本地歌单和本地优先数据边界的前提下，完成一轮可追踪、可回归、可线上验收的 CPlayer 发布可靠性加固：

1. Pages 产物能够证明它对应本次提交；
2. Service Worker 的预缓存资源变更有自动约束，不能只靠人工递增缓存号；
3. 桌面与移动浏览器回归覆盖后台/隐藏页面结束后自动切歌、四种播放模式、网络延迟和自动播放失败；
4. 歌手搜索能收齐接口报告的结果，覆盖重复、空分页、失败重试、旧请求污染和触摸滚动；
5. 本机播放诊断只保留脱敏的事件和错误摘要，不保存或上传 API 密钥、API 地址、播放进度以外的敏感数据。

## 验收标准

- 发布产物包含可公开读取的 commit/构建标识；本地构建、Pages workflow 和线上页面三者标识一致。
- 预缓存资源清单由构建产物生成并被静态测试校验；资源变更而缓存版本未变化时质量门禁失败。
- Actions 使用当前官方兼容的 Pages 相关 action 版本，workflow 不再引入 Node.js 20 弃用警告。
- 移动项目测试通过顺序、单曲循环、列表循环、随机四种模式；页面隐藏、结束事件重复、下一首网络延迟和 `NotAllowedError` 均不重复切歌或丢失可恢复状态。
- 搜索测试证明重复结果去重、空分页继续/停止规则、失败重试、旧请求丢弃和触摸滚动不会污染结果。
- 诊断报告可查看、清除和导出（若已有导出入口），内容不含 API key、API base URL、音频 URL、完整请求地址、token、歌名以外的敏感数据或播放时间点；播放进度只用于本机恢复，不进入诊断上报。
- `npm run verify`、桌面/移动 Playwright 回归、发布前置检查全部通过。
- 变更独立提交、推送后 Pages quality/deploy 成功；线上通过直接 CDP 验收页面标识、Service Worker 状态和缓存内容。

## 范围边界

- 不安装或要求用户准备 Android SDK、ADB、Appium 或实体手机；可用资源存在时再追加验证，否则以真实 Chrome CDP 和 Playwright 移动仿真明确记录边界。
- 不改 Supabase schema，不上传播放队列、最近播放、API 配置或播放进度。
- 不覆盖、删除或静默修改用户已有歌单和未提交改动。
