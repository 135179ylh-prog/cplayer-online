# 分页乱序与离线重试回归补强

## Goal

补齐上一轮侦察报告列出的搜索分页覆盖缺口，并修掉其中暴露的真实缺陷。

## 结论摘要

原定"修复同一查询内分页乱序污染"**不需要改产品代码**：先测量再动手，探针证明
该路径通过 UI 不可达（三层 in-flight 守卫），详见 `research.md`。本轮改为把这
条不变量用能抓住回归的测试锁住，并补齐真正缺失的离线/超时分页覆盖。

## Requirements

1. **先测量再改代码**
   - 任何"这是 bug"的判断都必须先用可运行的探针证实，不能只靠读代码推断。
   - 若路径不可达，不为它加生产代码或测试钩子。

2. **新测试必须经变异验证**
   - 每个新回归都要故意破坏对应产品代码，确认测试会失败。
   - 抓不住缺陷的测试要重写，直到压住行为不变量而非某一层实现细节。

3. **补齐分页失败覆盖**
   - 离线：断网分页保留已加载结果与真实进度，重连后从失败游标续传。
   - 超时：连接停滞（fetch 层失败）保留结果，重试只打失败游标。
   - 与既有 HTTP 503 用例走不同代码路径。

4. **游标不变量**
   - 分页进行中控件禁用；滚动与直接点击都不能重复请求同一游标。
   - 无重复行，进度文字不少报已渲染数量。

5. **消除长跑下的假失败**（本轮中途发现）
   - 全量门禁第 9 层出现 30s 超时失败，非断言失败，与本轮改动无关。
   - 必须根治而非靠重跑：`retries: 0` 使单次偶发直接把整层判为失败。
   - 不用重试掩盖——重试会让真缺陷在第二次偶然通过而被放过。
   - 改为放宽 per-test 预算，并用契约同时锁住"重试保持 0"和"预算为 90s"。

## Acceptance Criteria

- [x] 三类新回归各自通过变异测试验证有效
- [x] `search-recovery.spec.mjs` 由 18 项增至 24 项，桌面/手机双视口
- [x] 静态契约锁住新增回归标题与离线/超时中止原因
- [x] 超时根因经历史耗时数据量化，非凭单次失败推断
- [x] 新增的两条配置契约经变异测试验证能抓住回退
- [ ] 完整 `npm run verify` 十层通过
- [ ] 独立提交、推送、Pages 成功、`npm run check:release` 线上验收

## 安全约束

- 保留用户已有 5 项未提交改动，不暂存、不覆盖、不删除歌单。
- 变异测试用的产品代码改动必须全部还原并核对 diff 为空。
- 不强制推送，不改写远端历史。
