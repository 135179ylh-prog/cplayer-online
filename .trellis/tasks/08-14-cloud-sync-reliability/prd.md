# PRD - 云同步与本地恢复可靠性冲刺（第二阶段）

## 目标

让 CPlayer 在云同步边界出错时仍然保持本机数据安全、账号隔离且可恢复。重点处理请求进行中切换账号、响应丢失后的安全重试、注销清理失败后的刷新恢复，并把这些边界变成桌面/手机可重复验证的契约。

## 范围

- 同一页面已有同步请求时再次触发同步：只保留必要的后续任务，不重复覆盖本机状态。
- 同步请求完成后账号已经切换或退出：旧账号响应不能写入新账号的歌单、待办、错误或健康状态。
- 云端写入成功但客户端没有拿到响应：重试不能静默覆盖更新，也不能丢弃本机待同步记录；用户能看到明确的冲突/重试路径。
- 账号注销或本机脱离云账号时 IndexedDB 清理中断：刷新后依据本机标记继续清理，且不删除本机歌单内容。
- 退出登录后的待同步数量、错误记录和健康报告只反映当前账号或明确的本机待办，不泄露其他账号的歌单名称、歌曲或云端凭据。
- 健康检查在同步、账号切换、注销恢复和待办变化后保持过期标记正确。

## 验收标准

1. 同步进行中切换账号或退出登录，旧请求完成后不能改变新账号的歌单、outbox、冲突数、错误信息或成功时间。
2. 同一 outbox 在重复触发同步、网络重试或响应丢失后，最多形成一次有效版本推进；若服务端版本已变化，必须进入可解释的冲突/选择流程。
3. 模拟注销已成功但本机脱离标记尚未清除，刷新后能完成 owner 标记、历史和 outbox 的隔离清理；本机歌单名称和歌曲仍保留。
4. 清理失败期间重新登录其他账号，不会读取、展示或修改前一账号的待办和错误记录。
5. 桌面 `1280×800` 与手机 `390×844` 均覆盖主路径和典型失败路径；失败测试必须先证明持久化状态，再检查 UI 状态。
6. 不把 API key、API 地址、会话令牌、密码、完整媒体 URL或播放进度写入新增诊断、恢复包、云同步请求之外的持久化数据或日志。
7. 更新本任务 PRD、设计、实施计划、研究和验证；完成定向测试、`npm run verify`、独立提交、推送、Pages 成功和线上验收。

## 非目标与安全边界

- 本轮默认不修改 Supabase 表结构或 RPC 签名；只有在客户端证据证明必须增加服务端幂等键时，才另行记录外部迁移风险并请求确认。
- 不删除、覆盖或迁移用户已有歌单；不清理工作区已有未提交改动。
- 不把调试信息上传到第三方服务。
