# PRD：同步健康检查进行中状态变化的过期保护

## 目标

让同步健康检查不会把检查开始后发生的账号切换、待同步数量变化、同步状态变化或冲突变化误报成当前新鲜结论。

## 背景

现有报告用全局 `cloudHealthRevision` 判断新鲜度，但异步检查结束时直接把“结束时的 revision”写入报告。若检查期间发生状态变化，旧检查可能因此看起来仍然新鲜；账号切换在部分状态相同的情况下也可能没有推进 revision。

## 验收标准

1. 健康检查开始时记录 revision 和当前账号身份；检查期间任一状态变化后，完成的报告必须显示已过期，导出按钮保持禁用。
2. 账号切换即使前后显示状态文字相同，也会使旧报告过期；报告不泄露账号 ID 或账号信息。
3. 重新检查后，报告基于新的只读快照恢复为新鲜，导出恢复可用。
4. 健康检查仍只读，不写入或删除 IndexedDB、localStorage、歌单、待同步队列或播放数据。
5. 桌面 `1280×800` 和手机 `390×844` 均覆盖至少一条进行中状态变化和一条账号隔离边界。
6. 不保存或上传 API key、API 地址、token、完整音频 URL、歌曲内容或播放进度。
