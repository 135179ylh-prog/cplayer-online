# 手机后台自动续播可靠性

## Goal

修复手机切到后台后，一首播放结束时列表循环和随机播放偶发停住的问题，使结束切歌优先使用播放期间已取得的下一首媒体信息，不在最脆弱的结束瞬间重新依赖歌曲 API。

## Requirements

- 当前歌曲成功开始播放后立即准备下一首，不再依赖延迟 2 秒的计时器。
- 预取结果必须包含下一首索引、歌曲 ID、规范化媒体 URL 和歌曲元数据；结束时仅在它仍与当前队列和播放模式计算出的下一首一致时使用。
- 列表循环和随机播放结束切歌优先消费有效预取结果，不再次调用 `/163_music`；没有结果、结果失败或已过期时继续走现有联网加载回退。
- 用户主动选歌正在加载时，旧歌曲的 `ended` 事件仍不得跳过用户选择；单曲循环、顺序末尾、失败自动跳过和手动上一首/下一首保持原合同。
- 保持原生 `HTMLAudioElement` 路径，不引入 WebAudio 播放路由、后台服务或付费依赖。
- 未登录完整可用；API 密钥、API 地址、队列、最近播放和进度仍只存本机。

## Acceptance Criteria

- [x] 下一首已预取后，即使结束时对应歌曲 API 的第二次请求被阻塞，列表循环仍切到下一首且该 API 总请求数保持 1。
- [x] 随机模式使用当前打乱顺序中的下一项，并复用与该索引匹配的预取结果。
- [x] 当前歌曲成功播放后不依赖 2 秒计时器即可启动下一首预取。
- [x] 队列或模式变化导致预取目标不再匹配时，丢弃旧结果并安全回退，不播放错误歌曲。
- [x] 用户主动选择的下一首仍优先于旧媒体的结束事件。
- [x] 桌面与手机浏览器回归通过，完整 `npm run verify` 通过，并更新 Service Worker 缓存版本和 Trellis 记录。

## Boundary

- 网页无法对“系统强制结束浏览器进程”作出保证；本任务解决页面仍存活、原生音频仍能播放时的结束切歌关键路径。
