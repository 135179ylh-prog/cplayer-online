# 冲突差异预览

## Goal

在已有云同步冲突选择前，向用户清楚展示本机歌单与云端歌单的差异，避免用户在不了解内容的情况下盲目覆盖任一版本。

## Requirements

- 冲突卡片显示本机与云端的歌单名称和歌曲数量。
- 明确显示名称变化、仅本机存在的歌曲、仅云端存在的歌曲、同一歌曲信息变化和顺序变化。
- 差异预览只读，不改变本机歌单、云端歌单、回收站、历史版本或 outbox。
- 用户仍必须明确选择“使用本机”或“使用云端”后才执行现有冲突处理。
- 未登录或未配置云同步时，播放器和本地歌单继续完整可用。
- 预览使用统一的本地/云端歌曲规范化结果，不包含 API 密钥、API 地址、播放队列、最近播放或播放进度。
- 桌面 1280×800 与手机 390×844 均可阅读、操作，无横向溢出，按钮保持至少 44px。

## Acceptance Criteria

- [ ] AC1：冲突出现时，用户能看到名称、歌曲数量和至少四类差异摘要。
- [ ] AC2：本机独有和云端独有歌曲按歌曲名与歌手展示；没有对应差异时显示“没有”。
- [ ] AC3：同一歌曲元数据变化会显示本机和云端两份文本；顺序变化会显示两边的前几首顺序。
- [ ] AC4：预览期间不产生写入；点击原有处理按钮后仍按原逻辑处理并继续同步。
- [ ] AC5：桌面/手机浏览器回归和完整 `npm run verify` 通过。
- [ ] AC6：本里程碑有独立 Trellis 文档、提交、推送和线上验证记录。

## Out of Scope

- 本里程碑不实现自动合并或逐首合并编辑。
- 不改变 Supabase 表结构、RPC、IndexedDB 版本或同步决策。
