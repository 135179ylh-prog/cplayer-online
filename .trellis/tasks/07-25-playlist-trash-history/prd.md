# 删除回收站与历史版本

## Goal

让用户误删歌单或误改歌单内容后，能够在产品界面中找回数据；恢复过程必须本地优先、可见、可验证，不能静默覆盖现有歌单。

## Background

- 云端歌单表 `cplayer_playlists` 已有 `deleted_at` 和版本号。当前删除 RPC 只写入删除时间并增加版本，歌曲内容仍保留在原记录中。
- 当前本机会在删除歌单后立即从 IndexedDB 移除该歌单，并写入删除同步任务；其他设备收到 tombstone（删除标记）后也会立即移除本机记录。
- 当前同步接口会返回带删除标记的歌单，也允许同一歌单重新变为有效状态，因此已有能力可作为“恢复”的基础。
- 当前没有回收站页面、历史版本表、保留期限、永久删除或自动清理机制。
- 当前云端列表的 500 行限制会把已删除记录也计算在内。
- 现有测试已覆盖删除标记的同步决策和桌面/手机删除传播，但没有覆盖查看、恢复、永久删除和历史版本。

## Requirements

### R1. 数据安全

- 删除歌单不得立刻造成不可恢复的数据丢失。
- 恢复不得静默覆盖同名歌单、同 ID 的较新内容或其他设备上的并发变更。
- 恢复和永久删除都必须有明确结果反馈；失败时保留可重试的数据。

### R2. 本地优先与隐私边界

- 未登录时播放器继续完整可用；本地歌单同样具备回收站、历史版本和恢复能力，这些能力不能依赖登录才能运行。
- 登录后只同步账号下的自建歌单及其恢复所需数据。
- ChKSz API 密钥、API 地址、播放队列、最近播放和播放进度继续只保存在本机，不进入回收站云数据或历史版本。
- 继续使用现有 Supabase Free 与 GitHub Pages 方案，不引入付费服务或必须常驻的服务端进程。

### R3. 回收站

- 用户能查看已删除歌单，并看到足以识别它的信息和删除时间。
- 回收站项目保留 30 天，并显示剩余时间；到期后自动永久清理。
- 用户能从回收站恢复歌单。
- 用户能主动永久删除回收站中的歌单；永久删除必须二次确认，并说明不可恢复。
- 永久删除允许离线执行：本机确认后立即隐藏项目并持久保存待同步任务；同步完成前在同步状态中心明确显示，失败时必须可重试。
- 登录状态下的删除、恢复和永久删除应按现有本地优先同步机制跨设备传播，离线操作可排队，联网后收敛。

### R4. 历史版本

- 用户能查看歌单的历史版本，并至少看到版本时间和歌曲数量。
- 每个歌单最多保留最近 20 个历史版本，且每个版本最长保留 90 天；任一限制先达到时清理最旧版本。
- 用户能预览某个历史版本，再明确选择恢复。
- 恢复历史版本必须形成可追踪的新变更，不能直接抹掉恢复前的当前版本。
- 正常恢复沿用原歌单 ID；若同一 ID 已存在较新的有效歌单，则保留现有歌单，并把待恢复内容创建为名称带“（已恢复）”的新歌单。

### R5. 可观察与可恢复

- 回收站和历史版本的待同步、失败与冲突状态应接入现有同步状态中心。
- 网络中断、刷新页面或关闭浏览器后，尚未完成的恢复相关操作不能静默丢失。
- 30 天到期清理在应用启动或同步时执行；离线时写入持久任务，联网后再完成云端清理。
- 永久删除会清除歌单名称和歌曲内容，但保留不含内容的最小删除标记，防止长期离线设备把已永久删除的歌单重新上传。

## Acceptance Criteria

- [ ] AC1：未登录用户删除本机歌单后，可在本机回收站找到并恢复；刷新页面后数据仍在。
- [ ] AC2：登录用户在设备 A 删除歌单后，设备 B 能在回收站看到；任一设备恢复后，两台设备最终收敛到相同歌单内容。
- [ ] AC3：断网时可删除或恢复，界面显示待同步；联网后待同步数量归零且数据正确。
- [ ] AC4：存在并发修改时，恢复不会静默覆盖较新内容；若同一 ID 已有较新有效歌单，则现有歌单保持不变，恢复内容以带“（已恢复）”后缀的新歌单出现。
- [ ] AC5：用户可查看最近 20 个且未超过 90 天的历史版本摘要、预览内容并恢复；恢复后，恢复前的版本仍可追溯。
- [ ] AC6：永久删除需要二次确认；成功后名称和歌曲内容被清除，各设备最终都不再展示该回收站项目；离线或失败时同步状态中心显示持久待同步任务并允许重试；未手动处理的项目在删除满 30 天后自动清理。
- [ ] AC7：回收站和历史版本只包含自建歌单数据，不包含本机专属的 API 配置、队列、最近播放或播放进度。
- [ ] AC8：相关桌面与手机自动化测试通过，完整 `npm run verify` 通过。
- [ ] AC9：Trellis 需求、设计、实施和验证文档已更新；本里程碑独立提交、推送并在线上真实验证后，才能进入下一个里程碑。

## Out of Scope

- 恢复播放队列、最近播放、播放进度或 ChKSz API 配置。
- 恢复外部音乐源中已经失效或被删除的歌曲资源。
- 引入 Supabase 之外的新云服务或付费基础设施。
- 本里程碑不实现“冲突差异预览”的完整体验；它属于下一里程碑，但本阶段必须继续安全阻断冲突。
